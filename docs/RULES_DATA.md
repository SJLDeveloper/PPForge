# Rules data — sources and provenance

PP Forge's game knowledge (Powers, Pros & Cons, Perks and Flaws for each ruleset) is kept as data, not code. This document records where that data came from, how it was produced and checked, and how to change it.

## Source documents

| Document | Edition / content | Used for | Where it's kept |
|---|---|---|---|
| **Prowlers & Paragons Ultimate Edition** (`Prowlers_&_Paragons_Ultimate_Edition.pdf`) | The core rulebook as printed | `data/core_rules.json`; core-only rules in `RulesetConfig`; engine test cases (Chapter 2 walkthrough, sample heroes) | The owner's Claude Project "Prowlers and Paragons Character Sheet" (purchased copy) |
| **Combined Updates** (`Combined_Updates.pdf`) | The errata and rules updates for UE, reorganized by chapter | `data/errata_rules.json`; Roles; errata-only rules in `RulesetConfig` | Same Claude Project |

The PDFs are **not in this repository** and must not be added: they are copyrighted, purchased material. The repository holds only the derived mechanical data described below.

### What the data contains

- **Mechanics:** Power names, range, rank type (Power, Baseline, Default, Special), Hero Point cost structure, Power-specific Pros and Cons with their exact signed values, the generic Pros and Cons, Perk costs, and Flaw kinds (ordinary, Plot Hook, Condition, varies).
- **Classification:** whether each Power counts toward starting Resolve under that ruleset's rule, and grouping categories (Super Senses, Form, Transformation).
- **Summaries:** one or two short sentences per item, **paraphrased** so players can recognize the entry. No rulebook text is reproduced. Players need the books for the full rules.

The data does **not** include prose rules, tables beyond what costing needs, sample characters, setting material, or art.

## How the data was produced

Both data files are generated by Python scripts in `tools/`. The scripts are the editable source; the JSON is the build output. Running them reproduces the committed JSON byte for byte (checked on 30 Oct 2026).

| Output | Generator | Method |
|---|---|---|
| `data/core_rules.json` | `tools/build_core_rules.py` | The full text of the core rulebook (about 15,600 lines) was extracted from the PDF. A first-pass parser found the Power headers (`Range • Rank • Cost`) and the `PRO`/`CON` option lines. Every entry was then reviewed by hand against the text, correcting header costs that wrap onto a second line, ranges such as "−1 to −4", per-rank and per-Source modifiers, and multi-option costs. Summaries were written fresh. |
| `data/errata_rules.json` | `tools/build_errata_rules.py` | The Combined Updates text could only be read in parts (the first ~260 KB directly, the rest through targeted passage searches), so each errata Power, generic Pro/Con, Perk and Flaw was entered by hand from those passages. Every value was copied from the errata text, not carried over from the core book. |

The schema for both files is documented in [`tools/SCHEMA.md`](../tools/SCHEMA.md). The Rust types that read them are in `src/rules.rs`.

### Coverage

| | Powers* | Generic Pros & Cons | Perks | Flaws |
|---|---|---|---|---|
| Core | 141 | 53 | 12 | 48 |
| Errata | 144 | 54 | 12 | 48 |

\*Super Senses, Forms and (in the core book) Transformation are stored as individual sub-Powers, so these counts are higher than the books' Power index entries. Every name in each book's Power index is present, either as itself or through its sub-Powers.

## Verification

| Check | Core | Errata |
|---|---|---|
| Every Power in the book's index present | ✔ (scripted check against the index) | ✔ (scripted check against the index) |
| Every Power header (range, rank, cost) matches the book | ✔ Automated cross-check of all 141 headers against the extracted text. The only difference is wording: Determination is "5 Hero Points per 1 Resolve" in the book and per-unit 5 in the data. | Checked by hand during entry; **no automated cross-check** (see Open items in DESIGN.md) |
| Every `PRO`/`CON` line captured with the exact signed value | ✔ Automated comparison of all 102 lines in the core Powers chapter | Checked by hand during entry |
| Spot values asserted in unit tests | Regeneration 6, Quick Change 3, Evasion present | Regeneration 12, Quick Change 1, Strike 1 per 2 ranks, Parrying replaces the cost, Overkill raises the cap 3d, Dodge present (Evasion absent) |
| Engine reproduces published examples | Chapter 2 walkthrough hero = exactly 100 HP; a sample hero's Health/Edge/Resolve | — |

## Interpretations made while building the data

Where the text was ambiguous, the data records one reading and the app lets a GM override it:

- **Core Buff *Greater*** is printed without a sign; recorded as **+6**.
- **Core Deflection** is listed at 1 HP per rank, but the text allows 2 per rank to cover both physical and energy attacks, so it's stored as a per-rank choice of 1 or 2.
- **Hard to Kill / Immortality** have a higher cost when the Lethal Damage rules are in use. The core data keeps the standard cost and mentions the alternative in the summary; the errata data stores both as a choice.
- **Generic "−1 to −4" Cons** in the core book are really −1/−2/−4 steps. They're stored as ranges, and the UI offers every value in between.
- **Severe Flaws** (Severe Compulsion, Severe Reaction, Severe Requirement, Very Heavy) share an entry with the basic version (`kind: special`); the per-Flaw "+1 Resolve/issue" toggle selects the Condition version.
- **Resolve classification (core):** the book's rule is "Powers that can't attack, defend, or affect other characters or objects don't affect Resolve", with examples. The book's examples are marked, plus other pure movement, sense and utility Powers that fit the rule (46 Powers are marked as not counting). **Errata:** only the Powers the errata explicitly says to ignore are marked (Detection, Expertise, Acute Sense, plus the rankless Determination and Preparation).

Rules differences that live in prose rather than tables (Roles, Summoning cost formula, maximum Flaws, Edge wording, Power renames) are in `RulesetConfig` in `src/rules.rs`, not in the data files. See [DESIGN.md §4.3](DESIGN.md#43-ruleset-differences).

## Changing the data

1. Edit the generator script (`tools/build_core_rules.py` or `tools/build_errata_rules.py`), not the JSON.
2. Regenerate from the repository root: `python3 tools/build_core_rules.py` and/or `python3 tools/build_errata_rules.py`.
3. Run `cargo test`. The rules tests catch structural breakage, and the engine tests catch cost regressions.
4. Regenerate the SBOM (the data files are listed in it with their hashes): `python3 tools/sbom.py`.
5. Note the change, and the page or section of the source document, in the pull request description.

If a later errata or edition is published, add it as a new ruleset (a new `Ruleset` variant, a new data file, and a new `RulesetConfig`) rather than changing an existing one in place, so that saved characters keep the rules they were built with.
